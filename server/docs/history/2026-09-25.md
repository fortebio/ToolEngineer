# 2026-09-25 — Quản lý log lỗi CSKH: thống kê + báo Telegram

Làm cùng phần app (mục Log đã nhận / Thống kê lỗi — `apps/fbt_rapid/docs/history/2026-09-25-quan-ly-log-cskh.md`).
**CHƯA DEPLOY.**

## Đổi

- `PUT /devices/{id}/logs` lưu thêm `fw` (≤40 ký tự, phiên bản bộ quét app rút từ log — client tự khai).
- Metadata log (`_log_meta`, dùng cho `/logs`, `/devices/{id}/logs`, `PUT /logs/{f}/status`) thêm
  `fw`, `errors`, `warnings`, `keys` (khoá lỗi+cảnh báo, bỏ `info`), `error_keys`. `findings[]` do client
  gửi được lọc lại (`_clean_findings`: bỏ phần tử không phải dict/thiếu `key`, mức lạ → `info`).
- `GET /logs/stats?days=90` (0 = mọi lúc; gác `ota_admin`): `{days, since, total, clean, device_count,
  counts, signs[], devices[] (30 máy), firmware[], daily[]}` — gom từ METADATA (cache mtime/size), không
  đọc `text`. **Khai báo TRƯỚC `GET /logs/{filename}`**, không thì "stats" rơi vào route file → 400.
- Báo **Telegram** khi có log mới: `config.LOG_NOTIFY_TELEGRAM_TOKEN` + `LOG_NOTIFY_TELEGRAM_CHAT` (cả hai mới
  bật), `LOG_NOTIFY_APP_URL` tuỳ chọn. Gửi trong thread daemon qua `urllib` (không thêm package), timeout
  10 s, mọi lỗi bị nuốt + in `type(e).__name__` (không in `e` — URL chứa token bot). Mẫu env:
  `deploy/fbt-receiver.env.example`.
- Test: `test_log_meta_fw_va_dau_hieu`, `test_log_stats`, `test_log_bao_telegram` → **136 passed** (máy Admin, venv IDF).

## Deploy (khi người dùng đồng ý)

1. `scripts/deploy.ps1 -Server -Target fbt-server` (chép cả `app/*.py`).
2. Muốn bật Telegram: tạo bot bằng @BotFather, thêm bot vào nhóm kỹ thuật, lấy `chat_id` qua
   `https://api.telegram.org/bot<token>/getUpdates`, thêm 3 dòng `FBT_LOG_NOTIFY_*` vào
   `/etc/fbt-receiver.env` (sudo — người dùng tự làm) rồi restart `fbt-receiver`.
3. Kiểm: `GET /logs/stats` không token → 401 (route sống); build + deploy web để có 2 mục mới.
