## Đổi chính sách: device POST LUÔN thêm hàng; Drive nhường (theo yêu cầu chủ dự án)
- Chủ dự án làm rõ: dedup CHỈ giữa Drive↔POST; còn **mỗi lần thiết bị POST = 1 hàng** (kể cả gửi lại y hệt). Đảo lại thiết kế "dedup mọi nguồn" trước đó.
- Chính sách chốt: (1) POST bản mới → +1 hàng; (2) POST lại trùng → +1 hàng nữa; (3) POST bản **đang chờ từ Drive** (posted_at NULL) → **nhận bản Drive đó, đánh dấu posted_at, không thêm hàng**; (4) Drive import → chỉ thêm nếu nội dung chưa có trong DB.

## Vá auth fail-open → fail-closed (đề xuất từ DANH_GIA_THI_TRUONG.md)
- `check_auth` cũ: chưa đặt token → cho qua TẤT CẢ (fail-open). Server chạy public qua Funnel nên nếu env token lỡ trống/lỗi cấu hình → API mở toang ra Internet.
- Sửa: chưa đặt token → **từ chối hết** (fail-closed) — thà 401 toàn bộ để phát hiện còn hơn lộ dữ liệu. Token hiện đang đặt nên không đổi hành vi thực tế, chỉ chặn chế độ hỏng. Cập nhật test (7 logic + 10 api pass). Cần restart để nạp.
