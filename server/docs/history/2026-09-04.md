## Nhận log máy từ nhân viên CSKH (tab "Chăm sóc KH" › Xử lý sự cố của app)

**Vì sao**: app Flutter thêm tab cho nhân viên chăm sóc khách hàng — cắm USB vào máy, đọc log
UART rồi bấm "Gửi log về kỹ thuật". Cần chỗ nhận + tra lại.

**Thay đổi**
- `app/config.py`: thêm `LOGS_DIR` (env `FBT_LOGS_DIR`, mặc định `~/fbt_server/logs`) và
  `MAX_LOG_TEXT` (4M ký tự). `main.py` tạo thư mục lúc khởi động.
- `app/main.py`: 3 route mới (đặt TRƯỚC mount `/app`):
  - `PUT /devices/{device}/logs` — body JSON `{text (bắt buộc), by, note, port, baud,
    captured_at, app, findings[]}` → ghi `LOGS_DIR/<device>_<UTC %Y%m%d_%H%M%S>_<sha8>.json`
    (ghi tạm + `os.replace`), trả `{ok, file, size}`. **PUT chứ không POST** vì catch-all
    ingest nuốt POST (cùng lý do OTA).
  - `GET /devices/{device}/logs?limit=` — metadata mới nhất trước, KHÔNG kèm `text`; glob theo
    tiền tố rồi kiểm lại field `device` (tên có `_` thì tiền tố không đủ).
  - `GET /logs/{file}` — bản đầy đủ. Tên file kiểm bằng regex `^[A-Za-z0-9_.-]{1,160}\.json$`
    (không dùng `safe_name` vì nó cắt 64 ký tự → đổi tên → 404 sai).
  - Auth: cửa chung `auth()` (token thiết bị/admin đều qua) — nhân viên CSKH đăng nhập app là có token.
- `tests/test_api.py`: 7 test mới (401 không token, POST rơi vào catch-all → 400, ghi file +
  không để `.tmp-*`, thiếu `text` → 400, list/get + máy khác không thấy, tên file xấu, traversal
  bằng `\` qua `safe_name`). Khối `if __name__ == "__main__"` chuyển xuống CUỐI file (đang đứng
  giữa → chạy `python tests/test_api.py` bỏ sót test phía sau).

**Kết quả test (venv fastapi 0.11x + httpx, máy dev)**: 19/20 pass. Test cũ
`test_ota_tai_file_bin_va_chan_path_ban` fail ở `GET /ota/../../note.md` → **405** thay vì 404:
httpx mới chuẩn hoá `..` trước khi tới router nên request thành `GET /note.md` → khớp catch-all
POST → 405. Không liên quan thay đổi hôm nay; server thật vẫn không lộ file (path không tới
handler). Nên nới assert thành `in (404, 405)`.

**Deploy** (user tự làm — AI không restart production):
```
scp app/config.py app/main.py fbt-server:~/fbt_server/app/
ssh fbt-server "sudo systemctl restart fbt-receiver"
curl -s http://127.0.0.1:8080/openapi.json | grep -o '"/logs/{filename}"'   # kiểm route đã nạp
```
Không cần migration/GRANT (file, không DB). Thư mục `~/fbt_server/logs` tự tạo.
